# ASD-STE100 Simplified Technical English, Issue 9
# Term pack: SOFTWARE AND IT OPERATIONS
#
# What this file is: a list of subject-field words for software user guides,
# API and administration documentation, runbooks and DevOps procedures.
# Each entry is a technical noun (TN) or technical verb (TV) that a writer
# may use in STE text for this domain.
#
# What this file is NOT: it is not part of the official ASD-STE100 dictionary
# and it does not change it. The official dictionary holds general words only.
# Technical nouns and technical verbs are allowed by rules 1.5 and 1.12.
#
# How each entry was checked: against Issue 9 rule 1.5 (technical nouns, 22
# categories), rule 1.12 (technical verbs, 4 categories), rule 1.6 (words not
# in the dictionary, allowed only as technical nouns), rules 1.7 and 1.10
# (no technical noun used as a verb, no slang or jargon), rule 1.11 (one name
# for one item), and the dictionary status of each word.
# Words that are approved in the dictionary with a meaning that covers the
# software use are not listed as terms (see the comment blocks at the end).
#
# Columns:  term | TN or TV | category | std or ext[; note]
#   TN / TV  technical noun / technical verb
#   category rule 1.5 category number for nouns (6, 7, 9, 11, 15, 18, 19, 20, 21)
#            or rule 1.12 verb category for verbs (2a input/output,
#            2b user interface and application processes, 2c system operations)
#   std      the word appears in the standard's own example list for that category
#   ext      added by this project by the same principle (not in the examples)
#   note     dictionary status and usage advice:
#            "general sense: use X" means the common sense of the word is not
#            approved and X is the approved alternative for that sense
#
# Lowercase terms unless a capital is part of the name. Max three words
# (rule 2.1); a hyphenated group counts as one word.
#
# A company term base or a company glossary overrides this file.
# Where two names are used for one item, both are listed with a note, and
# the writer must use only one of them in a document (rule 1.11).

# approved words, no entry needed (their approved sense covers the software use)
#   verbs: close, open, select, start, stop, connect, disconnect, send, record,
#          monitor, install, erase, attach, compress, activate, deactivate,
#          release, cancel, make sure, try, again, go, remove, keep, write, tap,
#          verify (use make sure), retry (use try again), detach (use disconnect),
#          reconnect (use connect again), terminate (use stop), kill (use stop),
#          log (use record), reinstall (use install again), sync (informal, use
#          synchronize), attach
#   nouns: interface, display, data, error, exit, access, task, incident,
#          maintenance, test, procedure, step, method, row, group, copy, paste,
#          volume (plain noun; the compound "storage volume" is not listed),
#          patch (plain noun; "software patch" is listed), manual (plain noun)
#   "tap" is an approved verb meaning to hit lightly and quickly, so it is not listed as a technical verb.
#
# jargon and slang, and the proper term to use instead (rule 1.10)
#   bug                -> defect (category 7)
#   repo               -> repository
#   prod, production   -> production environment
#   config             -> configuration, configuration file
#   app                -> application
#   creds              -> credentials
#   sync               -> synchronize
#   kill (a process)   -> stop
#   terminate          -> stop
#   bounce (a service) -> restart
#   nuke, wipe         -> erase, delete
#   brick (a device)   -> set to OFF, or describe the result
#   gear (equipment)   -> tools and equipment
#   hotfix             -> software patch
#   whitelist          -> allowlist
#   blacklist          -> blocklist
#   cron job           -> scheduled task
#   spin up            -> start, provision
#   repo-based terms, pod, and similar platform names are not listed; use the generic term
#
# terms considered and not listed for other reasons
#   tweet (std 2b and 19) is social media, not used in software documentation
#   crash (verb) is informal in software text, use stop responding or fail
#   spam, quarantine as a verb, and sleep/wake are informal or not needed
#   fail (verb) is not approved, use failure (n) or fail over for the system case
#   click or tap as a noun form, log as a noun, and sign-on forms are left to the company term base
